# SafeHeaven ERC-2771 Blockchain Integration Guide

## Overview

This guide explains the ERC-2771 meta-transaction integration in SafeHeaven, allowing users to interact with the blockchain **without paying gas fees**. The backend admin wallet acts as a relayer, submitting transactions on behalf of users.

---

## Architecture

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   User Frontend │     │  Backend Relayer  │     │  Smart Contract │
│   (MetaMask)    │────▶│  (Admin Wallet)   │────▶│  (ERC-2771)     │
└─────────────────┘     └──────────────────┘     └─────────────────┘
       │                        │                        │
       │ 1. Sign Message        │                        │
       │    (No Gas)            │                        │
       │───────────────────────▶│                        │
       │                        │                        │
       │                        │ 2. Verify Signature    │
       │                        │ 3. Submit Transaction  │
       │                        │    (Pays Gas)          │
       │                        │───────────────────────▶│
       │                        │                        │
       │                        │                        │ 4. _msgSender()
       │                        │                        │    returns User
       │                        │◀───────────────────────│
       │                        │                        │
       │ 5. Transaction Result  │                        │
       │◀───────────────────────│                        │
       │                        │                        │
```

## Key Components

### 1. Smart Contracts

#### TrustedForwarder.sol
- Inherits from OpenZeppelin's `MinimalForwarder`
- Manages approved relayers
- Handles meta-transaction forwarding

#### TouristSafetyERC2771.sol
- Inherits from OpenZeppelin's `ERC2771Context`
- Overrides `_msgSender()` to return the original user
- Stores critical safety data on-chain

### 2. Frontend (React + ethers.js)

**Files:**
- `src/lib/blockchainService.ts` - Core blockchain service
- `src/hooks/useBlockchain.ts` - React hook for easy integration

**Features:**
- EIP-712 structured data signing
- MetaMask wallet connection
- Signature generation for meta-transactions

### 3. Backend (Node.js + ethers.js v6)

**Files:**
- `server/blockchain/relayer.js` - Relayer service
- `server/routes/blockchain.js` - API endpoints

**Features:**
- Signature verification
- Nonce management
- Transaction submission
- MongoDB sync

## Setup & Deployment

### Prerequisites

1. **Node.js** v18+
2. **MetaMask** browser extension
3. **MongoDB** (local or Atlas)
4. **Infura/Alchemy** account (for testnet/mainnet)

### Step 1: Install Dependencies

```bash
# Install frontend dependencies
npm install

# Install server dependencies
cd server && npm install

# Install contract dependencies
cd ../contracts && npm install
```

### Step 2: Configure Environment Variables

**Frontend (.env):**
```env
VITE_API_BASE_URL=http://localhost:3000/api
VITE_CONTRACT_ADDRESS=0x0000000000000000000000000000000000000000
VITE_CHAIN_ID=31337
```

**Server (server/.env):**
```env
MONGODB_URI=mongodb://localhost:27017/safehaven_sas
PORT=3000
ADMIN_PRIVATE_KEY=your_admin_wallet_private_key
SEPOLIA_RPC_URL=https://sepolia.infura.io/v3/YOUR_PROJECT_ID
```

**Contracts (contracts/.env):**
```env
ADMIN_PRIVATE_KEY=your_admin_wallet_private_key
SEPOLIA_RPC_URL=https://sepolia.infura.io/v3/YOUR_PROJECT_ID
ETHERSCAN_API_KEY=your_etherscan_api_key
```

### Step 3: Deploy Smart Contracts

#### Local Development (Hardhat Network)

```bash
cd contracts

# Start local blockchain
npm run node

# In another terminal, deploy contracts
npm run deploy:local
```

#### Sepolia Testnet

```bash
cd contracts

# Deploy to Sepolia
npm run deploy:sepolia
```

#### Ethereum Mainnet

```bash
cd contracts

# Deploy to Mainnet (requires significant ETH)
npm run deploy:mainnet
```

### Step 4: Update Configuration

After deployment, update the following:

1. **server/blockchain-deployment.json** - Auto-generated by deployment script
2. **frontend/.env** - Set `VITE_CONTRACT_ADDRESS` to deployed contract address

## Usage Examples

### Frontend: Connect Wallet & Register

```typescript
import { useBlockchain } from './hooks/useBlockchain';

function RegistrationForm() {
  const { 
    connectWallet, 
    signAndRegister, 
    isConnected, 
    address 
  } = useBlockchain();

  const handleRegister = async (formData: any) => {
    try {
      // Connect wallet if not connected
      if (!isConnected) {
        await connectWallet();
      }

      // Sign and submit registration
      const result = await signAndRegister({
        username: formData.name,
        email: formData.email,
        phone: formData.phone,
        dateOfBirth: new Date(formData.dob).getTime() / 1000
      });

      console.log('✅ Registered on blockchain:', result.data.txHash);
    } catch (error) {
      console.error('❌ Registration failed:', error);
    }
  };

  return (
    <form onSubmit={handleRegister}>
      {/* Form fields */}
      <button type="submit">
        {isConnected ? 'Register on Blockchain' : 'Connect Wallet'}
      </button>
    </form>
  );
}
```

### Frontend: Update Safety Status

```typescript
import { useBlockchain } from './hooks/useBlockchain';

function SafetyControls() {
  const { signAndUpdateStatus } = useBlockchain();

  const sendEmergency = async () => {
    try {
      // Status: 0=Safe, 1=Alert, 2=Danger/Emergency
      const result = await signAndUpdateStatus(2);
      console.log('✅ Emergency sent:', result.data.txHash);
    } catch (error) {
      console.error('❌ Failed to send emergency:', error);
    }
  };

  return (
    <button onClick={sendEmergency}>
      🚨 Send Emergency Alert
    </button>
  );
}
```

const signature = await signer.signTypedData(domain, types, message);

## Security Considerations

### 1. Private Key Management

⚠️ **CRITICAL:** Never commit private keys to version control!

```bash
# Add to .gitignore
.env
**/.env
server/.env
contracts/.env
```

### 2. Signature Expiration

All signatures include a deadline (default: 1 hour). Expired signatures are rejected.

### 3. Nonce Management

Nonces prevent replay attacks. Each user has an incrementing nonce tracked by the backend.

### 4. Admin Wallet Security

For production:
- Use a dedicated relayer wallet
- Implement transaction rate limiting
- Monitor wallet balance
- Consider using a hardware wallet or custodial service

## Troubleshooting

### "Blockchain not initialized"

- Ensure contracts are deployed
- Check `server/blockchain-deployment.json` exists
- Verify `ADMIN_PRIVATE_KEY` is set

### "Invalid signature"

- Ensure MetaMask is connected to correct network
- Check contract address matches deployment
- Verify chain ID in frontend matches network

### "Invalid nonce"

- Clear `server/nonces.json` (development only)
- Ensure user hasn't submitted duplicate requests

### "Transaction failed"

- Check admin wallet has sufficient ETH for gas
- Verify contract is deployed to correct address
- Check Hardhat/backend logs for detailed error

## Gas Optimization

The ERC-2771 pattern optimizes gas by:
1. Batching multiple user actions into single transactions
2. Using calldata instead of storage where possible
3. Efficient event logging for off-chain tracking

---

## Migration from Legacy System

If migrating from the non-blockchain version:

1. Deploy contracts
2. Run migration script to register existing users on-chain
3. Update frontend to use blockchain hooks
4. Enable hybrid mode (MongoDB + Blockchain)
5. Monitor and verify transactions
6. Switch to blockchain-primary mode
